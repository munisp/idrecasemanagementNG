Writes: multi-step writes run in Postgres transactions (case initiate = row + outbox event in ONE tx; bulk claims = tx with rollback). External events go through the transactional outbox (tenant_*.outbox → relay → Kafka) — an event can never be lost after the row commits. Idempotency keys (Redis) make mobile/PWA retries replay instead of duplicate.
Documents: files are vault-sealed before MinIO; metadata row + doc-intel event + timeline entry + correspondence log written together; ShareBox consumes link uses atomically (UPDATE … WHERE uses < max_uses RETURNING) so concurrent use can't double-spend.
Money: Stripe webhook settles invoice + writes payments + financial_events + TigerBeetle double-entry leg (deterministic id = sha256(payment_intent) — webhook retries idempotent). QA-gated email: nothing leaves qa_reviews as SENT without approval + correspondence_log entry.
